# Архітектура агентної системи

> Режим, ухвалений радою одноголосно (9.25 з 9.5, поріг 6.333): **`parallel-shadow`** — детермінований шар контролю і аналітичні агенти будуються **одночасно**, але агенти мають нуль капіталу і нуль прав виконання, доки не поб'ють виміряну базову лінію.

---

## 1. Три рівні. Дозволи течуть тільки вниз

```
┌──────────────────────────────────────────────────────────────┐
│  РІВЕНЬ 2 — АНАЛІТИЧНІ АГЕНТИ (LLM, shadow, read-only)        │
│  ETF · Equity · Macro/Regime · Risk · Strategy · Devil's Adv. │
│  Виробляють: Артефакти доказу. Не виробляють: рішення.        │
└───────────────────────────┬──────────────────────────────────┘
                            │ пропозиції + докази
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  РІВЕНЬ 1 — ШЛЮЗ G (детермінований код, НЕ модель)            │
│  G(state, proposal) → {accept | reject | escalate}            │
│  Перевіряє інваріанти. Не має LLM усередині. Не має винятків. │
└───────────────────────────┬──────────────────────────────────┘
                            │ дозволені пропозиції
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  РІВЕНЬ 0 — РЕЄСТР І ЕКСПОЗИЦІЯ (детермінований, read-only)   │
│  Позиції · кінцевий материнський контрагент · overlap ETF ·   │
│  дюрація · готівка · звірка трьох брокерів · щоденний звіт    │
└──────────────────────────────────────────────────────────────┘
                            │
                            ▼
              ЛЮДИ — і тільки люди — виконують ордери
```

**Ключова властивість:** агенти Рівня 2 не можуть порушити інваріанти Рівня 1 **за побудовою**, а не за домовленістю — бо в їхньому рантаймі фізично немає креденшела з правом ордера. Це те, що робить паралельну збірку безпечною.

## 2. Рівень 0 — Реєстр і рушій експозиції

Детермінований сервіс. Жодного LLM у шляху даних. Це те, що має працювати першим і працювати завжди.

| Модуль | Що робить | Джерела |
|---|---|---|
| `ledger` | Єдиний реєстр позицій по трьох брокерах, зведений до кінцевого материнського контрагента | Freedom24 Tradernet API (**read-only ключ**), IBKR/інші read-only, Польща — імпорт CSV/виписок |
| `counterparty` | Експозиція за юрисдикцією **і за материнською групою**; стелі компенсацій; статус регуляторних дій | Реєстр + ручне поле статусу FRHC |
| `overlap` | Перетин холдингів ETF (ваговий) — рахуємо **самі** | Щоденні CSV емітентів (iShares, Vanguard, SPDR) |
| `duration` | Дюрація і чутливість облігаційної ноги: `ΔP/P ≈ −D_mod·Δy + ½C(Δy)²` | QuantLib + крива Treasury |
| `concentration` | Ефективна диверсифікація `N_eff = 1/ρ_avg`, а не кількість позицій | Матриця кореляцій за цінами |
| `report` | Щоденний звіт, який читає людина. Одна сторінка | — |

**Пастка, яку треба закодувати явно:** iShares публікує холдинги на **торговий** кінець місяця, Vanguard — на **календарний**. Наївний join дає хибний overlap ([F], `06-EVIDENCE.md` §D). Два «різні» ETF регулярно мають **60–80% спільних холдингів** — саме та прихована концентрація, заради якої цей рівень існує.

## 3. Рівень 1 — шлюз `G`

```
G(state, proposal) → {accept | reject | escalate}
```

**Стан системи:**

| Змінна | Визначення |
|---|---|
| `C(t)` | поточний капітал |
| `HWM(t)` | `max(C(0..t))` — історичний максимум |
| `D(t)` | `1 − C(t)/HWM(t)` — просадка |
| `phase` | `PRESERVE` \| `COMPOUND` |
| `E_j` | експозиція на контрагента `j` (агрегована **за кінцевим материнським власником**) |
| `s_i` | розмір позиції `i` |
| `w_a` | вага довіри агента `a`, **скоупнута за доменом** |

**Категорійне правило, яке рада вивела окремо і яке легко порушити:**
`D(t)` — це **змінна фазового шлюзу**, а не предикат аварійної зупинки. Просадка замикає перехід у `COMPOUND` і блокує **нові** позиції. Вона **ніколи** не змушує продавати. Зупиняти систему можна лише на порушенні інваріантів незворотності (див. `03-CONTROLS.md`).

Плутанина між «спостережуваною величиною» і «порушеним інваріантом» — це те, що перетворює систему захисту на машину примусового продажу на дні.

## 4. Рівень 2 — аналітичні агенти

Це те, що ви замовляли. Воно будується. Але воно **виробляє докази, а не рішення**, і не має жодного шляху до грошей.

| Агент | Володіє | Зобов'язаний видати | Не має права |
|---|---|---|---|
| **ETF-аналітик** | Всесвіт ETF: TER, AUM, ліквідність/спред, метод реплікації (фізична/синтетична), контрагент свопу, політика securities lending, перетин холдингів | Картку фонду з полем джерела на кожне число + матрицю overlap проти наявних позицій | Казати «диверсифіковано» без порахованого overlap |
| **Equity-аналітик** | Окремі емітенти: owner earnings (діапазон, не точка), боргове навантаження, межа компетенції, три фальсифікатори тези | Тезу + **умову її спростування** + діапазон вартості, ніколи не точку | Виходити за межу компетенції без явного прапорця |
| **Macro / Regime** | «Де ми зараз» за спостережуваними: спреди оцінок, кредитні умови, крива, реальні ставки, стан кореляцій stock↔bond | Опис поточного стану + сценарії з діапазонами | Видавати прогноз як факт |
| **Risk-аналітик** | Розмір позицій (≤ ½ Kelly), дюрація, `N_eff`, стрес-сценарії, ризик контрагента | Числа, пораховані **кодом** (QuantLib / Riskfolio-Lib), не моделлю | Використовувати Sharpe/beta/VaR як рейтинговий інструмент — вони ненадійні на товстих хвостах ([F], §C) |
| **Strategy** | Синтез: що робити, за яких умов, з яким розміром, з яким виходом | Пропозицію у форматі, який приймає `G` | Пропонувати плече, маржу, деривативи |
| **Devil's Advocate** | **Обов'язковий.** Атакує кожну пропозицію, що стосується G0–G1 | Спробу спростування з названою конкретною вадою | Погоджуватись за замовчуванням |
| **Chronicler** | Незмінний лог: входи, промпти, версії моделей, джерела, часові мітки, рішення людей | Аудиторський слід | Редагувати минуле |

**Devil's Advocate має працювати на іншій моделі або іншому провайдері.** Причина не стилістична: агенти на спільній базовій моделі мають спільні сліпі зони, і це проявляється як **безпідставна згода**, а не як правильність. Це та сама помилка ρ→1, яку рада визнала за собою (див. §Convergence risk у вердикті).

## 5. Контракт обміну — Артефакт доказу

Єдина структура, якою обмінюються всі рівні. Число без джерела **відхиляється схемою**, а не рев'ю.

```json
{
  "claim_id": "etf.vwce.ter.2026-08-12",
  "claim": "VWCE ongoing charge is 0.22%",
  "value": 0.0022,
  "unit": "ratio_annual",
  "source_url": "https://...",
  "retrieved_at": "2026-08-12T09:14:03Z",
  "method": "document_extraction | api_fetch | computed",
  "computed_by": "riskfolio-lib==7.x | null",
  "evidence_label": "empirical | mechanistic | strategic | ethical | heuristic",
  "confidence": { "schema": "probabilistic", "p": 0.85, "resolution_date": "2026-11-12" },
  "falsifier": "Фактичний TER у річному звіті фонду відрізняється від 0.22%",
  "outside_view": { "base_rate": "...", "inside_estimate": "..." },
  "agent": "etf-analyst",
  "model": "…",
  "domain_scope": ["etf"]
}
```

Обов'язкові поля, кожне з яких закриває конкретний режим відмови:
- `source_url` + `retrieved_at` → галюциновані числа;
- `falsifier` → теза, яку неможливо спростувати, не є тезою;
- `confidence.resolution_date` → без дати розв'язання калібрування неможливо виміряти. **«Виміряти калібрування» — це не специфікація**, доки не задано ймовірнісну схему й механізм розв'язання;
- `outside_view` → підміна базової ставки внутрішнім поглядом;
- `domain_scope` → **вага довіри не переносить домени**. Це не абстракція: у самому Bridgewater інвестиційна репутація Дженсена була використана для вирішення кадрового спору ([F], §A). Компетентність в ETF не дає права голосу щодо кастодіана.

## 6. Протокол незгоди — як агенти сперечаються

Взято з механіки Bridgewater, але з виправленням її задокументованої вади.

1. **Наосліп.** Кожен агент видає свою оцінку **до** того, як побачить чужі. Інакше «дебати» — це каскад якоря, а не докази.
2. **Знеособлено.** На етапі крос-допиту авторство приховане: оцінюється аргумент, а не джерело.
3. **Дві таблиці голосів одночасно** — проста (один агент = один голос) і зважена за довірою. **Розбіжність між ними — це сигнал на ескалацію до людини**, а не привід автоматично взяти зважену.
4. **Довіра скоупнута за доменом** і заробляється двома умовами разом: щонайменше **три правильні виклики** + **причинне пояснення, чому це працює**. Одне без другого не рахується.
5. **Оновлення позиції лише з названою вадою.** Агент, що змінив думку, зобов'язаний назвати конкретну помилку у власному попередньому аргументі. Не може назвати — не оновлює.
6. **Тиша = поломка.** Місяць без зафіксованих незгод означає, що агенти корельовані. Це підстава видалити зайвого агента, а не привід радіти.

## 7. Люди: хто що вирішує

| Рішення | Принципал | Дмитро | Аналітики (Діма, Руслан, Володимир) | Система |
|---|---|---|---|---|
| Виставлення ордера | затверджує | другий підпис | готує | **ніколи** |
| Зміна порогу / θ | **тільки він**, поза каналом, із періодом охолодження | пропонує | пропонує | блокує до затвердження |
| Вибір / вихід із контрагента | **тільки він** | готує розрахунок | — | сигналізує |
| Розмір позиції | затверджує ліміт | застосовує в межах ліміту | пропонує | рахує ≤ ½ Kelly |
| Обхід правила (override) | **отримує сповіщення напряму, поза каналом Дмитра** | може ініціювати, **не може схвалити сам** | може ініціювати | логує незмінно |
| Допуск агента до впливу на капітал | затверджує | готує скоринг | — | рахує проти базової лінії |

**Правило подвійного підпису:** жодне виконання не проходить з одним підписом, і жоден із двох підписів не може бути «Дмитро сам».
**Правило маршрутизації:** kill-сигнали йдуть **напряму Принципалу, поза каналом керівника напряму** — той, хто структурно здатен переформулювати порушення як «контекст», не повинен бути першим, хто про нього дізнається.

## 8. Дані: що підключаємо

**Безкоштовний бекбон — спершу він, і лише потім платне:**

| Джерело | Що дає | Обмеження |
|---|---|---|
| SEC EDGAR / data.sec.gov | звітність, XBRL `frames`, повнотекстовий пошук | **макс. 10 запитів/с**, обов'язковий `User-Agent` з назвою організації і email — інакше 403 |
| FRED | макро, ставки, спреди, CPI | ~120 запитів/хв із безкоштовним ключем |
| ECB Data Portal / Eurostat | євро-зона, SDMX | без ключа |
| US Treasury | крива дохідностей (XML-фід) + fiscaldata JSON | без реєстрації |
| FINRA | short interest | двічі на місяць |
| Емітенти ETF | щоденні холдинги (CSV) | **недокументовані URL, ламаються** — обгортати моніторингом |

**Платне, що реально потрібне (орієнтир <€100/міс на команду):** EODHD (EOD €19.99 / фундаментал €59.99 / all-in-one €99.99, включно з Treasury rates beta і холдингами ETF) + Finnhub (60 запитів/хв на безкоштовному тарифі). Tiingo ($50/міс) має найдешевшу явну **комерційну** ліцензію. Marketaux ($29/міс) для новин з сентиментом на рівні сутностей. GDELT — безкоштовно, сильний на макро/геополітиці, слабкий на тикерах.

**Три ліцензійні пастки, які ймовірніші за проблеми з цінними паперами:** безкоштовні тарифи Finnhub, Tiingo і NewsAPI **забороняють комерційне використання**, а команда з чотирьох людей, що інвестує власні гроші, — це комерційне використання. NewsAPI комерційний старт — $449/міс, обходити.

**Брокерські рейки:**
- **Freedom24 Tradernet API** — публічний, документований, є офіційні MCP-сервери під Claude Code (MIT, червень 2026). **Вміє виставляти ордери.** Використовувати **виключно read-only ключ**, окремий процес, окремий контейнер.
- **IBKR** — TWS API / Client Portal → зводяться в один Web API з OAuth 2.0. Найкращий програмний шлях, якщо потрібен реальний read+execute розділ.
- **Польський банк (mBank / BOŚ / PKO BP)** — публічного роздрібного торгового API не знайдено. Проєктувати як **ручну ногу з файловою звіркою**.

## 9. Що НЕ будувати

- **Автономний торговий цикл.** Ні в v1, ні пізніше.
- **Дебатну петлю в стилі TradingAgents як продакшн.** Брати **топологію** (спеціалісти → опозиція → ризик-менеджер), не брати їхній торговий цикл: 357 відкритих issue, research-grade.
- **Донавчання моделей.** Позиційний сайзинг, ризик розорення, Kelly — усе це закриті формули. Fine-tuning не дає нічого, чого не дають формула і фід даних.
- **`backtrader`** — мертвий з серпня 2024 **і GPL-3.0** (копілефт-пастка для пропрієтарної системи). **`empyrical`** — мертвий, Quantopian не існує. **`vectorbt`** — ліцензія NOASSERTION, спільнотна версія комерційного продукту, **потрібен юридичний огляд**.
- **Формулювання на кшталт «найкращий у класі», «нагороджений».** ESMA (ESMA35-43-3861, 2023) прямо каже: **неявні рекомендації рахуються**, а вирішує подача й персоналізація, а не намір. Вихід системи — це докази, сценарії й діапазони, ніколи не «купуй AAPL».

**Що брати:** QuantLib (BSD, живий — облігаційна нога), Riskfolio-Lib (BSD-3 — CVaR, HRP, risk parity, моделі просадок), PyPortfolioOpt (MIT, **репозиторій переїхав** у `PyPortfolio/PyPortfolioOpt`), quantstats (Apache-2.0 — звіти). OpenBB — як шар абстракції даних, **перевіривши ліцензію** перед вбудовуванням. `ai-hedge-fund` (MIT) — найзручніша ліцензія, брати як каркас патернів.
